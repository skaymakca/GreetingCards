# Changelog Viewer

Parses `CHANGELOG.md` and generates HTML pages for the "What's New" viewer.

**Key files:**
- `app/core/content/changelog_models.py` — dataclasses (`ChangelogVersion`, `ChangelogGroup`)
- `app/core/content/changelog.py` — parsing and HTML generation logic
- `app/gui/dialogs/changelog.py` — viewer only (GUI shell)

## How It Works

`generate_changelog_html()` (entry point for `make content`):

1. Reads `CHANGELOG.md` from project root
2. `_parse_changelog()` parses Markdown into `ChangelogVersion` objects (version, title, date, body_html)
3. `_group_by_minor()` groups versions by MAJOR.MINOR (one HTML page per group)
4. `_generate_changelog_html()` renders Jinja2 templates to produce sidebar + content HTML files
5. CSS is shared via `../common/css/viewer.css` (no copy step needed)
6. JS is included via `../common/js/search.js`

The parser handles `##` headings, `- ` bullets, `**bold**`, `*italic*`, paragraphs, and date extraction from parenthesized suffixes. No external Markdown library needed.

## Templates

HTML is generated from Jinja2 templates in `content/html/templates/`:

- `base.html.j2` — shared DOCTYPE/head/body layout with sidebar and content blocks
- `changelog_page.html.j2` — extends base; renders sidebar with version groups and content with version entries

Templates use `autoescape=True` for safety. Pre-rendered `body_html` from the parser is passed through the `|safe` filter.

## Generated File Structure

```
_build/runtime_content/html/
├── changelog/              ← gitignored, generated by make content
│   ├── index.html          ← latest version content (alias for newest group)
│   ├── page_order.txt      ← navigation manifest (read at runtime)
│   └── pages/
│       ├── 0.9.html
│       ├── 0.8.html
│       └── 0.6.html
└── common/
    ├── css/viewer.css      ← shared stylesheet (referenced via ../common/css/viewer.css)
    └── js/search.js        ← shared search/highlight functions
```

Each page has sidebar + content HTML structure matching help pages. Sidebar hrefs are sibling-relative in page files and child-relative in index.

## Page Navigation

`get_page_order(base_path)` in `content/changelog.py` reads `page_order.txt` from the generated output directory. This manifest is written during generation with version pages in descending order. See `docs/architecture/html-viewer.md` for the shared manifest pattern.

## Menu Integration

Help menu → "What's New" → calls `show_changelog(parent)` → `show_viewer()` with `singleton_key="changelog"`.

## Make Target

```makefile
content:
    uv run python -c "..."  # generates help, changelog, and licenses HTML
```

Both `run` and `app` targets depend on `content`.
